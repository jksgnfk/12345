0 现状与目标

先把「多端」拆成三层，避免把「能在手机上打开」误当成「多端可用」。

层次含义当前状态
① 屏幕适配手机 / 平板 / 电脑都能正常操作、不缩放、不横向溢出已完成 响应式断点、16px 输入防 iOS 缩放、安全区、表格转卡片、触控 42px、深色主题
② 数据一致任一设备的改动，其他设备能看到已实现 新增本站共享后端（server.js + /api/state），网页各设备共用一份数据；重新发布后线上生效
③ 与小程序同源网页与微信小程序读写同一批报销单、公告、材料需网关 浏览器无法直连微信云开发数据库，且云存储只有 fileID

两条硬约束决定了架构：

  • 微信小程序的数据在云开发环境 cloud1-d7go7cz1ccef43aa4（records / announcements 集合 + uploads 云存储），浏览器不能直连；官方推荐做法是云函数 HTTP 访问服务做网关。
  • 云存储只保存 fileID，网页要下载材料必须先在服务端调 getTempFileURL 换临时链接（每批上限 100 个），并处理 CORS。
因此网页版的设计原则是：前端零密钥、零直连，所有云端访问都经网关；小程序链路保持不动，网页只是新增一个入口，不改动现有 8 个页面与 2 个云函数。
2026-11-07 更新 · 数据互通现有两条独立路线：
① 网页 ↔ 网页（多设备共享）：新增零依赖 Node 服务 web/server.js，同一进程托管静态页面并提供 /api/ping、/api/state、/api/file。前端自动探测，探测到即进入在线共享：写操作防抖上传、6 秒轮询 rev；服务端按 id + updatedAt 做记录级合并，删除通过 tombs 墓碑传播，旧数据不会覆盖新数据。不需要微信云开发控制台、不需要额外账号，重新发布一次即生效。
② 网页 ↔ 微信小程序：仍走下方 L1 的 syncGateway 云函数网关，需在云开发控制台启用 HTTP 访问服务并配置 SYNC_TOKEN。
2026-11-07 二次更新：新增 /api/file 按 key 存取材料原始二进制，材料文件本体也能跨设备共享——任一设备预览或导出时会按需取回真实图片，不再只剩文本清单。身份登记、审核密钥与未读状态仍只留在本机浏览器。
两条路线互不影响：以 file:// 打开或纯静态托管时自动降级为纯本地模式，原有功能全部照常可用。

2 分阶段路线

按「先能用、再自动、后实时」推进，任何阶段都可停，不需要一次性投入。

L0 · 已交付零部署 · 立即可用

快照搬运：一个 ZIP 把整台设备搬到另一台

网页版「数据管理 → 导出完整快照」会生成 records.json（单据 + 公告元数据）与 材料/ 目录（全部文件本体）；另一台设备「导入完整快照」即可完整恢复，材料可继续预览与导出。

  1. A 设备（电脑）导出 报销数据快照-YYYYMMDD.zip
  2. 通过微信文件传输助手 / 网盘 / 邮件把 ZIP 发到 B 设备（手机）
  3. B 设备打开网页版 → 数据管理 → 导入完整快照 → 选择 ZIP → 确认覆盖

适用：单人跨设备、偶尔同步、暂时没有域名或不想部署服务端。局限：手动触发、非实时、两端同时改会发生覆盖（后导入者胜）。

这一步不需要任何后台配置，是验证「多端是否真的好用」最低成本的起点。ZIP 为本系统自研 STORE 格式，中文名 + CRC 已验证。
L1 · 推荐起步静态托管 + HTTP 网关

一个网址，三端同源

把 web/ 目录整包部署到静态托管，手机 / 平板 / 电脑打开同一个 HTTPS 地址；数据统一经微信云开发 HTTP 访问服务的 syncGateway 云函数读写。网页版「数据管理 → 云同步」已内置客户端，填入网关地址与口令即可「测试连接 / 拉取云端 / 上传本地」。

  • 静态托管任选：腾讯云开发静态网站托管（同环境，最省事）/ GitHub Pages / Vercel / 内网 Nginx。
  • 网关：在云开发控制台启用「HTTP 访问服务」，新建 syncGateway 云函数并绑定路径；口令放在云函数环境变量。
  • 域名：自定义域名通常需备案；内部使用可先用云开发默认域名 + 限制访问口令。

同步粒度：先做全量拉取 / 全量上传（记录量在千级以内完全够用），配合「拉取前确认覆盖」提示，即可避免误覆盖。此阶段不做自动冲突合并。

L2 · 进阶近实时与冲突处理

从手动同步到自动同步

  • 触发：30 秒轻量轮询 /sync/pull 比对 updatedAt，或改用 SSE / WebSocket 推送变更；页面切回前台时立即拉一次。
  • 冲突：每条记录带 updatedAt 与 rev 版本号，服务端做乐观锁；同单据并发写时以「最后提交者 + 操作日志」保留双方改动，退回 / 阶段推进等动作建议统一走 auditStage 云函数，避免网页与小程序各写一套。
  • 材料：服务端用 cloud.getTempFileURL 分批（≤100）换链接；网页端 fetch 并发控制在 4–6，逐条释放 ArrayBuffer，避免单笔 50 份×多单据打爆内存。
  • 降级：网络失败自动切回本地模式，恢复后提示「有未同步改动」。
L3 · 可选身份与权限统一

把「口令」升级成「角色」

网关校验口令后签发短期会话，网页端按提交人 / 审核员 / 最高管理三角色控制可见范围与写操作；所有审核、退回、公告发布写入 audit_log 集合。与小程序现有 ADMIN_KEY='社畜' / AUDIT_KEY='天选打工人' 模型对齐，密钥只在服务端校验，前端不硬编码。

3 L1 架构与接口契约

网页只读/写入都经网关，小程序链路完全不动。

图 1 · L1 推荐架构：三端共用静态站点，经云函数网关访问与小程序相同的云开发环境

接口契约（网关与网页端均已按此实现）

路径请求体成功响应用途
POST /sync/ping{token, action:'ping'}{ok:true, env, time}测试连接与口令
POST /sync/pull{token, action:'pull'}{ok:true, records, announcements, fileUrls, updatedAt}全量拉取；fileUrls 是材料临时下载链接
POST /sync/push{token, action:'push', records, announcements}{ok:true, written, skipped, updatedAt}全量上传；云端较新的记录会被跳过

请求体同时带 action 与路径末段，网关两者兼容，不依赖 HTTP 访问服务的路径字段实现；响应为 {statusCode, headers, body} 标准结构，含 CORS 头与 OPTIONS 预检。失败统一返回 {ok:false, msg}；网页端已做 fetch 异常、非 2xx、业务失败、20 秒超时四层容错，任何失败都不影响纯本地模式。

材料同步边界：拉取时网关用 getTempFileURL 分批（每批 50 个）把云存储 fileID 换成临时链接，网页端尽力并发下载到本机文件仓库，失败不阻断（可再用完整快照补齐）。反向的「上传本地」只同步单据与公告元数据——网页端新添加的材料文件本体不会写回云存储，需要分片上传（L2）。
字段口径必须与小程序 utils/store.js 严格一致：STAGES（5 阶段）、MATNAME（7 类材料）、TYPE_MATERIALS、MAX_FILES=50、EXPIRE_MS=30天、记录 stage/stageLog/rejected/rejectLog/updatedAt。建议把常量抽成两端共享的 shared/constants.js，否则命名与阶段判断会逐步漂移。

4 云函数实现（L1，代码已就位）

完整可部署代码已写入 cloudfunctions/syncGateway/index.js 与 package.json，与现有 auditStage / announcement 同环境，无需新建服务。下方为精简示意，以工程内真实文件为准。

真实实现较示意补强五点：① skip 分批取全量（云函数单次上限 100 条，示意里的 limit(1000) 会被截断）；② 标准 HTTP 响应与 CORS / OPTIONS 预检；③ action 优先取请求体、兼容多种路径字段；④ push 按 updatedAt 拒绝旧数据覆盖并保留云端 _openid；⑤ pull 换取材料临时链接。
// cloudfunctions/syncGateway/index.js
const cloud = require('wx-server-sdk')
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })
const db = cloud.database()
const TOKEN = process.env.SYNC_TOKEN || ''   // 在云开发控制台配置，切勿写死在前端

exports.main = async (event) => {
  // HTTP 访问服务会把请求体放在 event.body（字符串）
  let body = event
  if (typeof event.body === 'string') {
    try { body = JSON.parse(event.body || '{}') } catch (e) { body = {} }
  }
  if (!TOKEN || body.token !== TOKEN) return { ok: false, msg: '口令错误' }

  const action = body.action || (event.path || '').split('/').pop()
  const rec = db.collection('records'), ann = db.collection('announcements')

  if (action === 'ping') return { ok: true, env: cloud.getWXContext().ENV, time: Date.now() }

  // 分批：云函数单次最多 100 条，skip 翻页取全量
  async function all(col, pages) {
    const out = []
    for (let i = 0; i < pages; i++) {
      const r = await col.skip(i * 100).limit(100).get().catch(() => ({ data: [] }))
      out.push(...r.data)
      if (r.data.length < 100) break
    }
    return out
  }

  if (action === 'pull') {
    const [records, announcements] = await Promise.all([all(rec, 20), all(ann, 5)])
    return { ok: true, records, announcements, fileUrls, updatedAt: Date.now() }
  }

  if (action === 'push') {
    const list = Array.isArray(body.records) ? body.records : []
    // 逐条 upsert；材料只同步元数据，fileID 指向同一云存储
    for (const x of list) {
      if (!x || !x.id) continue
      await rec.doc(x.id).set({ data: x }).catch(() => {})
    }
    for (const a of (body.announcements || [])) {
      if (!a || !a._id) continue
      await ann.doc(a._id).set({ data: a }).catch(() => {})
    }
    return { ok: true, updatedAt: Date.now() }
  }
  return { ok: false, msg: '未知操作' }
}

代码已就位，仅差三步控制台配置：

  • 部署：微信开发者工具右键 cloudfunctions/syncGateway →「上传并部署：云端安装依赖」；package.json 已配 wx-server-sdk ~2.6.3。
  • 开网关：云开发控制台 → HTTP 访问服务 → 绑定路径 /sync/* 到 syncGateway；在云函数环境变量中配置 SYNC_TOKEN（口令，务必自行设定），可选 SYNC_ORIGIN 限定静态站点域名。
  • 开材料下载：云存储 → 跨域设置（CORS）加入静态站点域名，否则浏览器拉取临时链接会被拦（此时仅单据元数据同步，材料可用完整快照补齐）。
  • 接通：网页端「数据管理 → 云同步」填 https://<网关域名> 与口令 → 点「测试连接」→「拉取云端」。CORS 头与 OPTIONS 预检已由网关返回，无需额外配置。
当前默认值仍是纯本地：未填网关地址时云同步客户端直接拒绝请求，网页版离线双击照常使用。不部署网关 = 完全不影响现有功能；部署后 = 手机 / 平板 / 电脑的网页与小程序连同一份云端数据。
材料文件本体不随全量 JSON 传输：小程序上传后存的是 fileID，网页端要取出真实文件需服务端 cloud.getTempFileURL({fileList}) 换临时链接（每批 ≤100），并在云存储配置 CORS。这也是「完整快照 ZIP」在 L0/L1 阶段依然有价值的原因 —— 它携带文件本体，可离线归档。

7 推荐落地顺序

  1. 现在就验证 L0：在工作台「数据管理」导出完整快照 → 用手机打开同一份 web/index.html（或先传到手机）→ 导入快照，确认单据、公告、材料都在，导出 ZIP 正常。
  2. 部署静态站点：把 web/ 整个目录上传到静态托管，拿到 HTTPS 地址；此时 PWA 生效，三端都能「添加到主屏幕」并离线打开。
  3. 启用网关：部署已写好的 syncGateway → 云开发控制台开 HTTP 访问服务并绑定 /sync/* → 配 SYNC_TOKEN → 测试 /sync/ping（代码无需再写）。
  4. 接通数据：网页版「数据管理 → 云同步」填地址与口令 → 测试连接 → 先「拉取云端」拿到小程序真实数据，确认字段无误后再启用「上传本地」。
  5. 按需升级：需要自动同步再加 L2 轮询与版本号；需要网页端正式审核再加 L3 角色与审计日志。
建议第 4 步先只读观察一轮：网页端保持只读，可完全规避与小程序 saveRecord 乐观更新的写入冲突；确认稳定后再开放上传。

9 本次新增：最高管理删除项目 & 默认下载到桌面

能力实现方式约束
最高管理删除项目「数据管理 → 项目管理 · 最高权限删除」：输入最高管理密钥解锁后，可单条或批量删除单据及其全部材料；详情抽屉的「删除单据」也仅对最高管理可见。删除经 saveState() 自动生成墓碑，其它设备打开同一链接时一并移除。审核员仍可退回 / 推进 / 导出，不能删除；操作前二次确认，不可恢复。
默认下载到桌面导出 ZIP、JSON 备份、完整快照与材料原文件统一走 download()；首次导出在用户点击手势内调用 showDirectoryPicker({startIn:'desktop'})，目录句柄存入 IndexedDB，之后直接写入该文件夹。浏览器不允许网页静默改写系统默认下载目录，需授权一次；不支持的浏览器自动降级为浏览器默认下载，并提示在「设置 → 下载内容 → 位置」改为桌面。
